# 共享带宽包 需求文档

> 状态：已确认（方向语义/规则侧交互/空包策略三项歧义已澄清）
> 前置：SNAT 双向限速已交付（docs/snat-delivery.md 增补）

## 问题陈述

当前限速以规则为单位（每条 snat 规则独立的上传/下载闸）。 когда 多条规则属于同一个业务
（如同一批办公网段出口），需要它们**合用一个总带宽额度**——任何一条规则用满额度，其他规则
 synchronization 挤压；同时需要能创建**多个独立**的带宽策略给不同业务分组使用。

## Scope

做：
- 新实体**带宽包**（BandwidthGroup）：名称唯一、**上下行合计单额度**（KB/s）、成员规则集合
- 成员关系**从带宽包侧管理**：打开带宽包后在其中选择/解除规则（snat 与 tcp/udp 转发规则均可）
- 规则加入带宽包后：**规则自身的限速字段不再生效**（保存校验提示；展示"由带宽包 X 管控"）
- 限速执行：同一带宽包的全部成员规则流量**共享**该包额度（合计不超额）
- 带宽包 CRUD + 成员增删 API + 前端管理页 + 规则表单/列表联动展示
- 删除保护：包内有成员规则时不可删除（需先解除）

不做：
- 上下行拆分额度（用户已选合计单额度）
- 规则侧选包（方向为包侧选规则——规则表单只读展示归属）
- tcp/udp 规则的规则级限速语义变化（未入包时行为不变）

## 用户故事

### US1 (P0) 创建与管理带宽包
- AC-1.1 WHEN 创建带宽包（名称+合计额度 KB/s+可空成员列表）THE SYSTEM SHALL 落库并立即
  对成员规则生效共享限速（tc 层重建）
- AC-1.2 重名拒绝；额度必须 >0；成员必须是已存在且启用的转发规则（任意协议）
- AC-1.3 修改额度后对全部成员规则实时生效（tc 重建，存量连接不断）
- AC-1.4 删除有成员的包 → 400 提示先解除；空包可删（成员规则恢复自由不限或自身限速？——
  解除的规则恢复"自身限速字段"语义，tc 重建）

### US2 (P0) 共享限速执行（核心）
- AC-2.1 GIVEN 包 P（额度 4096KB/s）含规则 R1、R2（同为 snat）WHEN R1 流量 3MB/s、
  R2 流量 3MB/s 并发 THEN 两规则合计被压到 ≈4MB/s（±20%；单规则不限更高）
- AC-2.2 包成员含 tcp/udp 与 snat 混合时同样共享（转发路径各自的 tc 挂点导入同一个共享 class）
- AC-2.3 规则加入/移除包、包额度调整均在 1 秒内生效（tc 重建窗口）
- AC-2.4 **规则自身限速字段在入包期间不生效**：规则表单保存时若已入包，上传/下载限速字段被忽略
  并提示；列表显示"带宽包 `<名称>`（合计 4096 KB/s）"

### US3 (P1) 前端管理页
- AC-3.1 侧边栏新增「带宽包」页：列表（名称/合计额度/成员数/成员摘要）、新建/编辑对话框
  （成员多选下拉列出全部启用规则，按协议分组显示）
- AC-3.2 「转发规则」「SNAT 穿越」规则列表：入包规则的限速列显示包徽标（替代数值）

## 成功标准

- SC-1 两规则共用 4096KB/s 包并发压测：合计 4MB/s ±20%
- SC-2 单成员规则独占包：单规则 ≈ 额度值 ±20%
- SC-3 解除成员后该规则恢复自身限速（或无限速）
- SC-4 go test ./... 全绿；161 热升级后现有规则 22 行为可退化（可被加入包）

## 非功能预算

- 无新第三方依赖；tc 结构复用现有 htb/ingress 形态
- 限速重建窗口 <1s；存量 TCP 连接不断（重建 qdisc 时连接保持）

## 假设与风险

- 假设：tc 共享 class（同一 htb class 被 multi-filter 引用）在内核的语义即"共享额度"——P2 PoC 验证
- 风险：成员规则跨多网卡（snat 若 In=A 网卡、另一规则 In=B 网卡）——共享额度需跨网卡同步（单网卡
  htb class 无法跨卡）→ P2 决策：包挂到各成员网卡独立的同额度 class（近似共享，各卡独立满额）或
  限速成员同网卡约束；首版从单网卡场景（当前现网）切入，跨卡包降级为"每卡独立额度"并文档声明
- 风险：规则启停/编辑导致 tc 重建时序与包重建竞争——引擎内串行化（Manager 锁）
