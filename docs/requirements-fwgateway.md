# 专线防火墙网关（fwgateway）需求文档

> 版本：v1 需求基线 · 状态：P1 待用户确认
> 前序文档：docs/requirements-snat.md（SNAT 穿越初版）、docs/requirements-snat-split.md（源/出口增强）、docs/requirements-bwgroup.md（带宽包）

## 问题陈述

lightgw 已在客户侧以内核转发形态提供 SNAT 穿越与用户态端口映射。现在客户把它部署在多公网 IP、多出口线路的机房入口，要求它承担**专线防火墙网关**的角色：入向把内网服务发布到指定公网 IP（DNAT），出向多出口冗余与分担，全程受有状态防火墙策略管控。同时，现有实现依赖 `iptables`/`ip` 外部命令下发内核规则，在最小化系统上不可用且无法支撑后续防火墙能力——本版本把内核转发机制统一收敛到 Linux 原生防火墙框架（nftables，经 netlink 直连内核下发，零 iptables 依赖）。

一句话：**多 IP、多出口、双栈的状态防火墙网关，内核线速转发，Web 管理面不变。**

## Scope

- 做：US1–US8（见下）
- 不做：
  - **网关模式全流量**（内网客户端把默认网关指向本机、全部流量受管）——已定两阶段演进，v1.1 增量；v1 保持"白名单穿越"接入形态（与现网兼容）
  - **tc 限速、conntrack 掐断命令的去除**——现功能保留 exec 形态不动（纯替换无新价值），v1.1 再评估
  - NAT64/DNS64（v4↔v6 互转）
  - IPsec/SSL VPN、DPI/IPS/应用层识别、URL 过滤
  - 双机 HA（VRRP）、会话同步
  - 动态路由协议（BGP/OSPF）
  - 新增应用层代理形态（现有 TCP/UDP 端口映射维持现状）

## 用户故事

### US1 (P0) nftables 基座迁移
作为运维者，我希望内核转发规则改为程序内 netlink 直连内核 nftables 下发，以便去掉对外部 iptables 命令的依赖，并为 DNAT/策略/多出口提供统一基座。
- 验收标准：
  - AC-1.1 系统无 `iptables`/`iptables-legacy`/`nft` 二进制的环境（最小容器验证），既有 snat 全功能正常：白名单穿越、目标黑白名单、限速、统计、停用即断、启动对账、热更新零中断
  - AC-1.2 与宿主既有规则共存：docker（iptables-nft 与 iptables-legacy 两类宿主）、firewalld 在位时，本产品规则生效且外来规则不被破坏（不 flush 整链/整表）
  - AC-1.3 从旧版本（iptables 形态在位）升级：首次启动自动检测并拆除旧形态，无双份叠加，穿越不中断超过 1 个探测周期
  - AC-1.4 出口策略路由（ip rule/ip route）同步去 exec 化，语义与现状一致
  - AC-1.5 `go test ./...` 与 `go vet ./...` 全绿，规则构造层有离线单测（不依赖内核权限）
- 边界与异常：netlink 操作失败（缓冲区、权限）要有可读错误且不半装（装一半失败需回滚）；nftables 内核能力缺失时启动即报错（不静默退化）

### US2 (P0) DNAT 端口发布
作为内网服务提供者，我希望把内网服务发布到本机指定公网 IP:端口，以便外部客户端直接访问且受策略与统计管控。
- 验收标准：
  - AC-2.1 外部客户端访问 `公网IP:端口` → 流量到达内网 `后端IP:端口`，回程自动还原（状态 DNAT，后续包不重复求值）
  - AC-2.2 发布 IP 可指定为出口网卡上任意归属 IP（一卡多址任选），非本机 IP 保存时报错
  - AC-2.3 源访问控制：可配源名单（谁能访问该发布端口），名单外访问被拒且拒绝计数可见
  - AC-2.4 后端健康检查（复用现有 health）：后端不可达时发布规则的拒绝行为与状态展示可预期
  - AC-2.5 停用/删除发布规则立即掐断存量会话（其他发布规则会话不受影响）
  - AC-2.6 IPv6 公网地址到 IPv6 后端的发布同样可用（NAT66，不做 v4↔v6 互转）
  - AC-2.7 流量统计/速率/`live` API 口径与现有规则一致（可区分上下行）
- 边界与异常：发布端口被本机服务占用时报错；同一公网 IP:端口不允许两条启用规则；后端不可达时新连接的失败模式明确（拒绝/超时二选一可配，默认拒绝）

### US3 (P0) 状态防火墙策略（ACL）
作为防火墙管理员，我希望按有序规则列表控制穿越流量（源/目的/协议/端口 → 放行|拒绝），已建会话自动放行，以便实现专线访问策略。
- 验收标准：
  - AC-3.1 策略规则有序（可调整优先级），先命中先适用；全部未命中走默认策略（v1 白名单穿越形态下转发默认拒绝，由穿越/发布规则的例外放行）
  - AC-3.2 匹配维度：源 IP/网段/名单组、目的 IP/网段、协议 TCP/UDP/ICMP(TCP/UDP 带端口或端口段)
  - AC-3.3 会话状态语义：established/related 会话不重复评估策略；新增拒绝规则对既有会话可选"立即掐断"或"仅拦新建"（默认仅拦新建）
  - AC-3.4 每条规则有命中计数（包/字节）与最近命中时间，Web 可见；策略变更热更新不中断既有转发
  - AC-3.5 会话表可视化：当前活跃穿越/发布会话（五元组、状态、出口、字节）可查询，与本轮统计口径不冲突
  - AC-3.6 策略增删改与顺序调整全部写审计
  - AC-3.7 IPv6 策略与 IPv4 策略各自独立生效
- 边界与异常：规则数上限（默认 1000，可配）防止规则面打爆内核；非法 IP/端口段保存时逐字段报错；策略与规则白名单叠加时的语义（策略拒绝优先）须文档化

### US4 (P1) 多出口：健康检查主备切换
作为多专线用户，我希望配置多个出口（网卡+网关+优先级）并自动探活，主出口故障时新流自动切到备用出口，恢复后回切。
- 验收标准：
  - AC-4.1 出口实体：网卡、网关、优先级、探测方式（ICMP 网关 / ICMP 远端目标 / TCP 目标端口）、周期与失败阈值可配
  - AC-4.2 主出口故障：在「失败判定时间 + 1s」内完成切换（默认周期 3s×2 次失败 → ≤7s），新会话走备用出口；切换事件审计 + 界面状态翻转
  - AC-4.3 切换时存量会话策略默认"掐断重连"（避免旧源 IP 从新出口发出的失配黑洞），可配"自然老化"
  - AC-4.4 主出口恢复：默认自动回切（可配不回切），回切只影响新会话
  - AC-4.5 出口状态可观测：实时状态（up/down/探测延迟/最近切换时间）在 Web 与 `/healthz` 可见
  - AC-4.6 IPv4 出口与 IPv6 出口分别探测、分别切换
- 边界与异常：全部出口 down 时新会话拒绝且告警；探测目标不可达与出口故障要区分（探测自身失败不触发切换抖动——连续 N 次才判 down）；出口网卡拔除（链路 down）立即判 down

### US5 (P1) 出口负载分担
作为多专线用户，我希望多条同级出口按权重分担新建会话，同一会话保持同一出口。
- 验收标准：
  - AC-5.1 出口带优先级与权重两层：流量先在最高可用优先级层内按权重分担，该层全 down 落到下一层（主备与分担统一模型）
  - AC-5.2 同一五元组会话始终同一出口（会话亲和），由内核转发路径保证（每流确定性选路）
  - AC-5.3 出口下线其权重退出分配，存量会话按 US4 策略处理；恢复后重新参与
  - AC-5.4 每出口新建会话数/字节数在 Web 可见
- 边界与异常：权重全 0 按等权处理；分担仅对新会话生效（存量不迁移）

### US6 (P1) 一卡多 IP 源地址选择（SNAT 池）
作为多公网 IP 用户，我希望出口网卡上的多个公网 IP 作为 SNAT 源池被规则使用。
- 验收标准：
  - AC-6.1 SNAT 源支持多 IP 池，分配策略三选一：固定单 IP（现状）/ 按会话轮换 / 源客户端粘滞（同源固定同出口 IP）
  - AC-6.2 池内 IP 必须归属出口网卡（保存校验 + 运行时复验，失配时规则状态告警而不静默黑洞）
  - AC-6.3 池成员从网卡移除：该 IP 不再分配给新会话，存量会话随旧映射自然老化（默认）或掐断（可配）
  - AC-6.4 IPv4 池与 IPv6 池独立
- 边界与异常：轮换以会话为单位（同一连接全程同 IP）；粘滞哈希在池成员增减时的重分配范围可控

### US7 (P1) 双栈 IPv6 贯穿
作为纯 IPv6 专线用户，我希望 v6 穿越与发布与 v4 同等可用。
- 验收标准：
  - AC-7.1 v6 SNAT 穿越（NAT66 源改写）、v6 DNAT 发布、v6 策略、v6 名单、v6 限速、v6 统计全链路可用
  - AC-7.2 前端表单对 v6 地址可用（校验、缩写规范化展示）
  - AC-7.3 v4/v6 混合部署不互相干扰（v4 规则不影响 v6 会话，反之亦然）
- 边界与异常：一条规则为单栈（地址族由地址形态推断），混合地址保存报错并指出字段

### US8 (P2) 万兆性能基线
作为万兆专线用户，希望网关在万兆环境下无拥塞瓶颈。
- 验收标准：
  - AC-8.1 部署包含调优（conntrack buckets/hashsize、sysctl、网卡多队列启用脚本），万兆环境一键适用
  - AC-8.2 真机基准（双万兆口对打）：单向 TCP ≥ 9 Gbps；64B 小包 pps 基准值出数并记录（首测基线，迭代回归）
  - AC-8.3 转发路径 CPU 占用基准记录（单核饱和点）
- 边界与异常：基准依赖真机环境，QA 虚拟环境不适用——真机验收项，notCovered 风险显式标注

## 成功标准

- SC-1 无 iptables/nft 二进制的最小环境，US2/US3 功能验收全过（容器 + 真机各一遍）
- SC-2 主备切换端到端收敛（接口断开 → 新会话走备用）≤ 10s
- SC-3 负载分担：15 分钟新建会话分配与权重比例偏差 ≤ 20%
- SC-4 SC-2/SC-3 在 1000 条策略规则在位时不劣化（切换收敛 ≤ 12s）
- SC-5 新增规则构造/编译层单测覆盖率 ≥ 70%

## 非功能预算

- 管理面：规则/策略热更新生效 < 1s；Web 界面加载不劣于现状
- 转发面：万兆基准见 AC-8.2；conntrack 容量默认调至 ≥ 50 万会话
- 兼容：从当前版本（74a2f85）平滑升级，既有 snat 规则数据无损迁移

## 假设与风险

- 假设：
  1. 部署环境 Linux 内核 ≥ 5.x、nftables 可用、程序以 root（或 CAP_NET_ADMIN）运行——与现部署基线一致
  2. 多出口 = 每出口独立网卡（或独立网关）；一卡双出口 v1 不支持
  3. 出口切换的"掐断存量"语义基于源 IP 失配黑室的工程判断（切换后旧源 IP 从新出口发出必被上游丢弃或非对称路由），P2 需真机验证
- 风险：
  1. **与宿主防火墙共存**（最高风险）：iptables-legacy 宿主上 nftables ACCEPT 无法覆盖 iptables FORWARD policy DROP（两套 hook 并行评估）；iptables-nft 宿主上 base chain 非终结 accept 同理。P2 必须专项设计（hook 优先级、基线脚本 gateway-firewall.sh 演进）+ 三类宿主（legacy/nft/firewalld）共存测试矩阵
  2. google/nftables 库边界：锁 v0.3.0；已知坑（批量 flush 缓冲区、IP 必须 To4()）在 PoC 卡（T001）验证；fail-fast 不静默
  3. QA 环境（WSL2）无内核 netfilter 权限：规则构造层全部离线单测化；内核面验收依赖真机（161 部署机或新环境），每里程碑一次真机回归
  4. 负载分担的每流确定性选路依赖内核转发路径能力（P2 PoC；不通过降级为按源哈希分配）
  5. 范围大：按里程碑 M1（基座迁移）→ M2（DNAT+策略）→ M3（多出口+池+双栈）→ M4（性能+交付）分四段，每段独立可回归、可暂停交付
- 里程碑即返工锚点：每个 M 结束跑一次全量回归，不带着已知缺陷进下一段

## 路线图（本 PRD 之外，不丢需求）

- v1.1：网关模式全流量（默认网关接入、三向区域 trusted/untrusted/DMZ）；tc/conntrack 命令 netlink 化
- v1.2+：NAT64、双机 HA、会话同步、出口bonding
