# SNAT 转发规则 需求文档

> 状态：待用户确认（P1 出口门）
> 背景：现有转发是四层代理（客户端 → 本机:port → 代理进程 → 目标），目标侧看到的源 IP 永远是本机。
> 本需求：流量从别的机器经本机**三层穿越**（进网卡 in → out 网卡出，内核转发不经代理进程），
> 出方向源地址需替换为本机出网卡 IP（SNAT），并叠加现有引擎的治理能力（限速等）。

## 问题陈述

192.168.10.161 是一台双网卡机器（ens19: 172.16.40.10/24 入口网段，eth0: 192.168.10.161/24 出口网段）。
上游机器（如 172.16.40.x）把网关指向 161 或将流量路由到 161 的 ens19，这些流量需要从 eth0 出去
访问 192.168.10.0/24（或其他经 eth0 可达的网络）。因为上游用的是私有网段地址（172.16.40.x），
直接转发出去后对端无法回包（缺 172.16.40.0/24 的回程路由），所以出口必须做 SNAT——源地址换成
eth0 的 192.168.10.161。同时运维需要像管理现有 TCP/UDP 规则一样管理这些穿越流量：限速、
黑白名单、流量统计与监控。

## Scope

做：
- 规则类型新增 `snat`：指定 入网卡 + 出网卡 +（可选）源网段白名单，由引擎配置内核 iptables nat 表
- SNAT 源地址取规则指定出网卡的当前主 IP（网卡 IP 变化时热更新）
- 复用现有引擎能力：限速（按规则的 per-rule 令牌桶 → tc 流控）、黑白名单组（iptables 匹配源 IP）、
  流量统计（iptables 计数 → 规则列表/`/api/metrics`）、实时速率（读计数差分）
- 管理页统一：规则列表/表单/启停/删除，与现有 TCP/UDP 规则同一交互
- 引擎失败自愈：规则删除/停用时同步拆除 iptables 规则（不留垃圾规则）

不做：
- IPv6（NAT66 语义不同，v2 再议）
- 端口映射/DNAT（本需求只有 SNAT 透传，不改目标地址与端口）
- 逐连接五元组会话表（穿越流量不经代理进程，无逐连接视图；统计为规则级聚合）
- 硬件卸载/性能调优（线速转发由内核 fast path 完成，tc 限速仅为治理手段）

## 用户故事

### US1 (P0) 运维创建 SNAT 规则，上游流量从指定入口网卡穿越、经出口网卡 SNAT 出去
- 验收标准：
  - AC-1.1 WHEN 创建 snat 规则（in=ens19, out=eth0, 启用）THE SYSTEM SHALL 在内核
    iptables nat 表 POSTROUTING 生效 `snat --to-source <eth0主IP>` 且 filter 表 FORWARD 放行，
    状态列为运行中
  - AC-1.2 Given 上游机 172.16.40.x（网关指向 161）When 访问 192.168.10.0/24 任意地址
    Then 流量经 161 ens19 进、eth0 出，**对端抓包/日志看到的源 IP 为 192.168.10.161**，业务回包正常
  - AC-1.3 When 停用/删除该规则 Then 对应 iptables 规则即刻拆除，穿越流量停止放行
  - AC-1.4 WHEN 出网卡 IP 变化（DHCP/手工改址）THE SYSTEM SHALL（下次 SIGHUP 热加载或重启时）
    重建规则指向新 IP，日志可见重建记录
- 边界与异常：入口=出口网卡（拒绝创建）；网卡不存在（拒绝创建，提示可用网卡清单）；iptables 写入
  失败（规则落库但状态=启动失败，last_error 可见，不影响其他规则）

### US2 (P0) SNAT 规则支持源网段白名单（哪些上游网段允许穿越）
- 验收标准：
  - AC-2.1 WHEN 规则配置源网段列表（如 [172.16.40.0/24]）THE SYSTEM SHALL 仅放行源在名单内的
    穿越，其余 ens19 进入的转发流量 DROP（ACCEPT 列表之外）
  - AC-2.2 WHEN 源网段留空 Then 放行该入口网卡进入的全部转发流量（宽松模式，提示风险）
  - AC-2.3 引用名单组（与 TCP/UDP 规则同一套白名单组）时，组变更联动生效（重建 iptables 规则）
- 边界与异常：名单元素非法（拒绝保存）；引用组（如同黑白组语义，SNAT 只用白名单语义）

### US3 (P0) SNAT 规则限速（入口维度）
- 验收标准：
  - AC-3.1 WHEN 规则配置上传限速 N KB/s THE SYSTEM SHALL 经 tc 在入口网卡 qdisc 挂 IfB/htb，
    入向带宽被限制在 N KB/s 附近（±20%，实测口径）
  - AC-3.2 WHEN 限速为 0 THEN 不挂任何 tc 规则（线速）
  - AC-3.3 WHEN 规则停用/删除 Then 对应 tc 类拆除，网卡 qdisc 恢复（无残留）
- 边界与异常：tc 工具缺失（规则可用但限速不生效，状态提示）；同网卡多条 snat 规则（tc 层共享
  入向带宽总闸，规则级各自 class）

### US4 (P1) 规则级流量统计与监控（穿越字节看不到逐连接，规则聚合数）
- 验收标准：
  - AC-4.1 规则列表实时列显示 SNAT 规则的 累计包数/字节数（读 iptables 计数器），
    `/api/metrics` 暴露 `haweb_rule_*` 族（bytes/packets/denied）
  - AC-4.2 实时速率为计数器差分的滑动窗口平均（B/s），与 TCP/UDP 规则同列展示
  - AC-4.3 `/api/rules/:id/live` 对 snat 规则返回包/字节与速率（无活跃连接数概念，恒 0）
- 边界与异常：计数器 64bit 回绕不做处理（标注）；iptables 计数读取失败（统计显示 0 且规则状态提示）

### US5 (P1) 健康检查与管理面安全
- 验收标准：
  - AC-5.1 snat 规则不参与 TCP 后端健康检查（无固定后端语义）
  - AC-5.2 iptables 全部链规则带 `-m comment --comment haweb-sn:规则ID` 标记，绝不全链 FLUSH——
    卸载/停用时按标记精确删除（不动系统既有规则，含 docker 的）
  - AC-5.3 升级交付：部署包/安装脚本不变（能力内置于二进制）；161 现网服务原地热升级到含 SNAT 的版本
- 边界与异常：升级降级（旧版本读新库 snat 规则行：忽略不识别的 protocol 字段值，不崩溃）

## 成功标准

- SC-1 172.16.40.x → 192.168.10.y 全链路连通且源 IP 呈现为 192.168.10.161（真机实测）
- SC-2 限速 2048KB/s 规则实测吞吐 2048±20%
- SC-3 停用规则后穿越流量在 2 秒内停止放行
- SC-4 既有 TCP/UDP 转发规则与全量回归测试不受影响（`go test ./...` 全绿）

## 非功能预算

- iptables/tc 子命令执行仅发生在规则变更时（创建/启停/删除/热更新），数据面零 exec（内核 fast path）
- 规则变更生效延迟 < 1s
- 不引入新第三方依赖（iptables/tc 经 os/exec 调用系统命令）

## 假设与风险

- 假设：161 的 ip_forward 已启用（实测为 1；安装逻辑不强改宿主机 sysctl，仅在规则启用且值为 0 时
  报错提示，避免越权改系统内核参数）。**待用户确认**：是否允许应用自动开启 ip_forward？
- 假设：入口流量经 ens19 到达且 ip_forward 生效时内核即尝试转发（上游网关/路由指向 161）
- 风险：iptables 规则残留（进程崩溃没走清理）→ 应用启动时按 `haweb-sn:` 标记全量对账，孤儿规则删除
- 飱险：与 firewalld/ufw/docker 的 FORWARD 链交互 → 只 ADD/DEL 自有标记规则，不碰外来链；
  FORWARD 默认策略若为 DROP，我们的 ACCEPT 规则需要 -I 插入队首（设计已含）
- 风险：tc 入向限速依赖 ifb 模块（modprobe ifb）；缺失时降级为不限速并状态提示（不阻塞主功能）
