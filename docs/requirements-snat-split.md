# SNAT/DNAT 菜单拆分与 SNAT 源/出口增强 需求文档

> 状态：P1 待确认（本需求方向在多轮现场协作中已与用户对齐：拆分菜单 + 指定源 IP + 出口网卡选 IP）
> 前置：SNAT 基础功能已交付（docs/snat-delivery.md，161 运行 fcf2857）

## 问题陈述

现在 SNAT 与 TCP/UDP 端口转发混在同一个「转发规则」列表里，两者语义完全不同（端口映射是本机监听代理；
SNAT 是内核层穿越转发），混排让运维心智负担大。且 SNAT 出口源 IP 目前固定取出口网卡第一个 IPv4，
一块网卡有多个地址（如运营商分配的公网池）时无法选择用哪个 IP 做 SNAT；源侧只有"白名单"概念，
用户需要显式的"指定哪些源 IP 走这条 SNAT"（语义更直白）。

## Scope

做：
- **菜单拆分**：侧边栏「转发规则」（tcp/udp 端口映射）与「SNAT 穿越」（snat 规则）两个独立页面/路由/API 过滤
- **SNAT 指定源 IP**：显式"源网段"字段（哪些源 IP 的流量走本规则；空 = 全放行，沿用现有语义兼容）
- **SNAT 出口 IP 选择**：出口网卡选定后，下拉列出该网卡上全部 IPv4 地址，任选其一做 SNAT 源
  （默认自动 = 第一个 IPv4，即现有行为）
- 161 现网规则兼容迁移（现有 snat 规则默认值平滑）

不做：
- DNAT/端口映射的能力变化（拆菜单不动 tcp/udp 功能本身）
- SNAT 的 IPv6、逐端口/协议细分（继续整卡粒度）

## 用户故事

### US1 (P0) 侧边栏两个独立菜单
- AC-1.1 侧边栏显示「转发规则」「SNAT 穿越」两个入口，各自只显示对应类型规则
- AC-1.2 直连 /api/rules?protocol=snat 只返回 SNAT（tcp/udp 同理 filter 参数均可用）
- AC-1.3 原 tcp/udp 规则的全部交互（创建/编辑/启停/删除/健康检查/组引用）在「转发规则」页不缩水
- AC-1.4 现有 snat 规则在「SNAT 穿越」页可见可管理，重启升级不丢

### US2 (P0) SNAT 指定源 IP（网段）
- AC-2.1 表单"源 IP 网段"输入列表（IP/CIDR 多条），保存后仅匹配这些源的流量走本规则 SNAT，
  其余流量（从入口网卡进入的）DROP
- AC-2.2 源列表为空 = 放行入口网卡全部穿越流量（现有 off 语义）
- AC-2.3 源列表与白名单是同一存储（allow_list），旧数据零迁移直读直用；引用白名单组仍然可用
- AC-2.4 iptables 安装形态：SNAT/ACCEPT 行带全部 -s 匹配（多值 OR 兜底 DROP 不变）

### US3 (P0) 出口 IP 选择（一卡多址）
- AC-3.1 表单选定出口网卡后，SNAT 源地址下拉列出该网卡**全部 IPv4**（含 secondary）；
  "自动"选项 = 网卡第一个 IPv4（默认）
- AC-3.2 保存后 iptables `--to-source` 使用选定 IP；规则列表/摘要显示该 IP
- AC-3.3 网卡地址后续变化时不自动改写规则（显式选择固化；"自动"选项跟随网卡首地址，热重载重应用时跟随）
- AC-3.4 `GET /api/interfaces` 返回每块网卡的地址列表（数组），前端下拉来源

### US4 (P1) 兼容与交付
- AC-4.1 升级路径：新版本读旧库 snat 行（无源列表/无显式出口 IP）等效"全放行+自动首地址"
- AC-4.2 全量回归 + 161 热升级后现有规则 19 行为不变（eth0→ens19、白名单 192.168.10.0/24、SNAT 172.16.40.10）

## 成功标准

- SC-1 两个菜单各自类型隔离（互不出现对方类型行）
- SC-2 SNAT 指定源 172.16.41.0/24 时：162（192.168.10.x）流量被拒、名单内源放行（真机或等价验证）
- SC-3 出口网卡配多地址后选择第二地址，iptables --to-source 正确指向该地址
- SC-4 go test ./... 全绿；161 热升级后规则 19 穿越功能不回退

## 非功能预算

- 无新第三方依赖；iptables 参数依旧数组直达 exec（无 shell 拼接）
- 接口新增仅 GET /api/interfaces 扩展（地址列表）与 rules 的 protocol 过滤参数

## 假设与风险

- 假设：一卡多址场景通过 ip addr add 验证（161 ens19 可临时加第二地址测试）
- 风险：拆菜单后旧书签/链接路径变化——保留 /rules 路由跳转到新两个页面之一（前端 redirect）
- 风险：SNAT 指定源与白名单组同时配置的语义重叠——沿用现有互斥（直配/组引用二选一）
